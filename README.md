# leetcode

> 力扣刷题笔记：202 道 LeetCode + 18 道卡码网 ACM 模式题，按 13 个主题整理的可检索题库

## 项目简介

这是我在 2024 年 7 月到 2025 年 2 月之间刷 LeetCode（力扣）的代码存档。原始 README 只有「力扣 hot100 刷题笔记」这一行说明，实际上题目范围早已超出 hot100：从数组双指针一路写到单调栈、树形 DP、并查集和欧拉路径，后期还混入了卡码网（Kamacoder）的 ACM 模式练习题。

所有题目都是**单文件、可独立运行**的形式：

- 文件名为题号，例如 `No206.java` 就是「206. 反转链表」；
- 每个文件里有一个与文件名同名的外壳类，`main` 方法里手写测试数据；
- 真正的解法放在 `SolutionXXX` 类里，一道题有多个解法时并列 `SolutionXXXOne / Two / Three`；
- 链表题、二叉树题直接复用 `ListNode` / `TreeNode` 两个自带 `init()` / `print()` 的辅助类。

所以这个仓库既是刷题记录，也可以当成一个「按题号查解法」的索引来用。

## 代码风格

- **注释**：228 个文件里 174 个带 IDEA 自动生成的 `Author daydream / Date` 头注释；正文注释以中文短句为主，写的是「为什么」而不是「是什么」，例如 `//把根节点的左右边路径加上根节点`、`//空间优化版`、`//本题为0-1背包问题`、`//相当于找出最长的公共子序列`。DP 题的注释最密，基本能把状态转移读出来。
- **复杂度**：只在 `No136`（只出现一次的数字）和 `No146`（实为 416 分割等和子集）两处写了复杂度说明，其余靠注释和代码本身体现。这是这个仓库最明显的短板。
- **多解法**：136 个文件只有 1 个解法类，54 个文件 2 个，8 个文件 3 个。第二个解法通常是「空间优化版」（DP 二维降一维）或「换一种数据结构」（哈希表 vs 双指针）。
- **测试方式**：没有单元测试，全靠 `main` 里手写一组数据 + `System.out.println` 打印结果，人眼看对不对。

## 技术栈与运行方式

- **语言**：Java，**需要 JDK 21**。仓库里没有 `pom.xml` / `build.gradle` / `.iml`，也没有 `.idea`，所以没有显式的版本声明——版本是从代码里实测出来的：
  - `No150`（逆波兰表达式）用了 `switch` 规则（`case "+" -> ...`），要求 JDK 14+；
  - `No107`、`No145`、`No151` 用了 `List.reversed()`，这是 JDK 21 的 `SequencedCollection` 新 API，要求 JDK 21；`--release 17` 编译会报「找不到符号: 方法 reversed()」，`--release 14` 还会先在 `No150` 报「不支持 switch 规则」。
  
  实测 `javac 21.0.9` 全量编译 0 错误 0 警告（`javac -d out src/*.java`）。
- **依赖**：零第三方依赖，只用 JDK 标准库。
- **组织方式**：所有文件平铺在 `src/` 下、都在默认包（无 `package` 声明），所以编译时必须一次性带上辅助类。

命令行编译运行（在仓库根目录）：

```bash
# 编译全部（输出到 out/，该目录已在 .gitignore 中）
javac -encoding UTF-8 -d out src/*.java

# 运行某一道题，例如 206 反转链表
java -cp out No206
```

用 IDEA 更省事：直接 `File → Open` 选仓库根目录，把 `src` 标记为 Sources Root，然后在任意 `NoXXX.java` 里点 `main` 旁边的绿色三角即可。

```
    ├── ListNode.java           # 链表节点 + init(int[]) / print()
    ├── TreeNode.java           # 二叉树节点 + init(Integer[]) / print()
    ├── Main.java               # 卡码网某题的草稿（滑动窗口 + 字符集计数）
    └── Test.java               # 相交链表的草稿解法
```

`ListNode` / `TreeNode` 是这个仓库的关键基础设施，两者都提供 `init()` 从数组建结构、`print()` 按层/按链打印，所以每道题只要写 `ListNode.init(new int[]{1,2,3})` 就能开始调试。

## 学习路线

按提交时间和题目分布，大致是四个阶段：

1. **2024 年 7—8 月 · 基础结构**：数组双指针、字符串、哈希表、栈与队列。这一段的简单题最密集（27、283、977、344、541、20、1047）。
2. **2024 年 9—10 月 · 链表与二叉树**：链表从 206 写到 25（K 个一组翻转），二叉树从三种遍历写到构造（105、106、654）和 BST 性质（98、530、538、450）。这一段注释最啰嗦，很多文件里能看到「先写错、再改对」的痕迹。
3. **2024 年 11—12 月 · 回溯、贪心、动态规划**：回溯 18 题（含解数独、N 皇后）、贪心 15 题、DP 38 题，是这个仓库的主体。背包问题（416、474、494、1049）和股票系列（121/122/123/188/309/714）各自成体系。
4. **2024 年 12 月—2025 年 2 月 · 图论与 ACM 模式**：转向卡码网，练岛屿类 DFS、并查集、拓扑排序，同时把输入输出从「写死数组」改成 `Scanner` 读。

想按这个仓库复习的话，建议顺序：先看统计表挑一个主题 → 打开该主题下题号最小的文件 → 只看 `main` 里的测试数据和 `class Solution` 的签名，自己写一遍 → 再对照文件里的多解法。

## 已知问题

- **没有构建脚本**：没有 `pom.xml` / `build.gradle`，也不能 `mvn test`。所有题目共用默认包，一旦两个文件出现同名类（例如两个 `Solution` 之外的公共类）就会编译冲突；目前能编过是因为类名都带了题号后缀。
- **文件名与内容不符 4 处**（复制模板后忘了改题号，建议后续修正文件名）：

  | 文件 | 实际内容 |
  | --- | --- |
  | `No146.java` | 416. 分割等和子集（0-1 背包，二维 + 一维优化两版） |
  | `No306.java` | 309. 买卖股票的最佳时机含冷冻期 |
  | `No736.java` | 763. 划分字母区间 |
  | `No1046.java` | 1049. 最后一块石头的重量 II |

- **重复题目 3 组**：`No146`≈`No416`、`No306`≈`No309`、`No736`≈`No763`，内容几乎完全一致，属于重复提交。
- **`No142.java` 名字是 142（环形链表 II），内容是 124（二叉树中的最大路径和）**——这一处更彻底，连解法都不是同一题，仓库里因此没有 142 的解法。合计有 5 个文件的题号与内容对不上。
- **`Main.java` 是半成品**：里面是卡码网某题的草稿（读 `n`、`k`、字符串后做滑动窗口），有 `import com.sun.source.tree.WhileLoopTree;` 这种 IDE 误导入的内部 API，换 JDK 可能编译不过，建议删除或标注为草稿。
- **`Test.java` 是草稿**：`main` 空实现，只有一段相交链表的旧解法，和 `Mianshi0207.java` 重复。
- **`Mianshi0207` 命名不统一**：其余面试题若存在也应统一为 `MianshiXXXX`，目前只有这一例。
- **没有复杂度标注**：202 道题里只有 2 处写了时间/空间复杂度，作为「笔记」用途偏薄。
- **无单元测试**：正确性靠 `main` 里手写的一组数据和 `println` 目测，回归时无法自动验证。
- **历史遗留**：早期文件（2024/7—8 月）里存在未使用的 import 和注释掉的旧代码块，例如 `Kama99`、`Kama105` 里大段 `/* ... */` 包起来的废弃实现。
